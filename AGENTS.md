# Repository boundaries

- After every complete functional update, run appropriate checks and generate a fresh installable VSIX using npm run package:vsix. Increment the patch version for a new functional build; report the artifact path. Release bundles must not generate or include SHA256 checksum files, per user preference.

- Production extension code belongs in src/. It must never import labs/.
- Experimental Qidian browser probes belong in labs/qidian/; they are not shipped with the extension.
- Tests for promoted production behavior belong in tests/. Browser feasibility probes are not production tests.
- docs/PLAN.md is the single shared design and progress record. Update evidence and pending items honestly after experiments.
- README.md is only for feature introductions and installation, connection and usage instructions. Keep development status, test evidence, experiment history and pending work in docs/PLAN.md; do not use README.md as a progress log.
- Never commit credentials, cookies, browser profiles, account details, bookshelf contents, chapter text, screenshots, or raw network traces.
- Only login, re-login and verification within that login flow may require manual official-page interaction. After login, bookshelf pagination, catalog/chapter retrieval, session recovery and local progress persistence must be automatic. Never require manual browser navigation, extraction clicks or Cookie copying as the reading workflow.
- Runtime access challenges fail automation acceptance: stop and report AccessBlocked instead of adopting recurring manual CAPTCHA handling. Do not automate purchases, subscription changes or bypass access controls.
- Do not claim VIP extraction or session persistence works without authenticated live evidence.
- Normal reading uses a hidden dedicated Edge window. Show it for manual login/re-login and hide it after verified login and task recovery. Access blocks and read failures stop the task with a VS Code notice. Provide explicit show/hide commands; an explicit diagnostic show must not be immediately overridden by automatic hiding. Control only windows positively identified as belonging to IdlePage's dedicated browser profile.
- The owning VS Code service must clean up its dedicated Edge and its lifetime guardian on exit. Keep one guardian per dedicated profile; never terminate ordinary Edge instances or unidentified process trees. Handle abrupt host exit independently of deactivate().
- Keep one confirmed bookshelf separately from reading task tabs. Keep one managed task tab after completion and at most two during navigation; retire the old tab only after acceptance, and preserve the previous chapter on failure. Explicit book selection retires old managed reading tabs even when the new catalog is cached, while preserving the bookshelf and VS Code's last readable body. Normal navigation never closes an unowned or user-navigated tab. The user's explicit full-refresh action may close all tabs of the positively identified dedicated Edge profile, preserving cookies and reading cache; ordinary Edge remains untouched. Never reopen the companion page to recover a task timeout while the dedicated Edge process already exists; report the connection failure instead.
- The normal entry is a native book Codicon in the status bar, with a trusted-command allowlist in its Markdown hover menu. No activity-bar icon or click/double-click action. Book/chapter selection uses native QuickPick; keep diagnostics out of the normal flow.
- Persist book/volume/chapter/body mappings only in private global storage. Default cache budget is 200 MiB including its index; use bounded atomic writes and chapter-first LRU eviction. Cache only successfully acquired content, with no automatic whole-book prefetch. Cache reuse is separate from reading-position persistence.
- Normal reading uses three native status-bar items (chapter index/total, segmented text, chapter percentage), with window-width percentage estimated rather than exact CSS sizing. Keep a serial rolling horizon of the next three chapters, reuse valid cache, and prioritize foreground navigation. Background results must never change the reading chapter, offset or catalog selection. Reading/prefetch failures stop and show status-bar diagnostics with explicit show-browser, return-to-reading and retry actions; do not automatically reveal a login window for these tasks. Returning to reading does not retry. Preserve the failed task page for manual inspection. Legacy diagnostic/login probes keep their dedicated recovery workflow.

- browser-extension/ contains the shipped browser template. Never add pairing credentials there; generate paired copies in VS Code globalStorageUri. Browser worker tests belong in tests/, separate from the labs prototype.
- Reading location is selectable from the top-level book hover menu: status bar (default), sidebar, or bottom panel. All locations share reading state and commands; switching location must not reset position or fetch content. Keep status-bar failure notices available for every location. Webview placement must not close the user's other views.
- First-use setup starts from the book hover menu and reports actionable steps in the status bar. After loading the paired browser extension, connection, login detection and bookshelf retrieval advance automatically. Mark setup complete only after confirmed online bookshelf extraction; errors/cancellation stop the guide without hidden retries.
