# IdlePage：方案与进度

更新日期：2026-10-13（Asia/Shanghai）。此文件是唯一共享的方案与进度记录，随 Git 提交推送到 GitHub；本机私有实验数据不参与同步。

## 目标与当前结论

制作自用 VS Code 状态栏小说阅读器，首要书源是起点中文网，仅账号登录及重新登录允许手动操作；登录后自动读取个人书架、目录及账号有权阅读的章节，并保存本地阅读进度。先验证接入，再实现正式阅读体验。

当前结论：Playwright 环境启用沙箱后仍出现访问验证，用户再次确认验证失败。普通 Edge 加入浏览器伴随扩展后可正常访问，用户反馈自动测试结果为 probe-complete / bookshelf，即首页到书架的自动访问路线本轮通过。2026-10-13 已提取当前页真实书单 11 本，用户核对一致；统一单章正文已真实回传 7021 字符，内容正确性待人工核对；自动分页、实际解锁限制提醒及跨进程会话复用未验证；此前独立桥接代码创建被自动审批拒绝。已实现 VS Code 扩展宿主内的回环 HTTP 服务；2026-10-13 修复浏览器轮询缺少 Origin 的问题后，普通 Edge 自动执行首页→书架并真实回传 VS Code，用户反馈与本机状态记录一致。已实现第一本书目录自动提取及分批回传；用户核对发现阅读进度快捷链接混入目录，其余条目正确。已修复该误识别，真实复测返回 225 章；用户确认第一章和章节顺序正确，第一本书目录提取核对通过。正式代码的 29 项单元/集成测试及真实宿主模拟书单、目录、正文成功和失败任务测试通过。不能宣称完整起点接入已完成。

## 接入路线

### 首轮实验：Playwright 专用浏览器（暂受阻）

使用本机 Edge，独立浏览器配置，人工完成网站登录和验证码；工具仅观察当前页面 DOM，不自动点击、购买、破解验证或反复刷新。

自动化浏览器配置：`%LOCALAPPDATA%/IdlePage/qidian-probe/edge-profile`。

初轮 Playwright 默认参数带有 `--no-sandbox`，已改为 `chromiumSandbox: true` 并实测运行进程不包含该参数。但重新验证后仍触发验证，不能将其认定为唯一原因或已解决风控。单次诊断脚本会自动关闭浏览器，曾打断用户验证；常规 session 模式已保留窗口直至用户关闭。

### 优先后续路线：普通浏览器伴随扩展 + 自动任务桥接（待验证）

普通 Edge 对照配置：`%LOCALAPPDATA%/IdlePage/qidian-probe/manual-edge-profile`，不包含 Playwright 控制、不启用远程调试、不导出 Cookie。用户已反馈此配置能正常访问并登录。

2026-10-12 需求修订：登录之后不得依赖用户切换到浏览器、打开书架、翻页、打开章节、点击提取或复制 Cookie。手动提取桥接不满足要求，不再作为实现路线。

候选链路：VS Code 应用用例 → 本机任务桥接 → 普通浏览器伴随扩展 → 起点页面加载和内容脚本 → 结构化书架/目录/正文 → VS Code 状态栏。

候选分工：
- 普通浏览器保有账号会话，伴随扩展按任务自动加载官方书架或阅读页；登录时显示官方页面供用户操作。
- 内容脚本自动等待目标 DOM 就绪并提取结构化结果，不要求用户点击扩展按钮。
- 本轮采用 VS Code 扩展宿主内的回环 HTTP 服务验证任务往返；Native Messaging 保留为候选，浏览器启动恢复机制待验证。普通浏览器可登录不代表带伴随扩展自动加载页面也可用。
- 本机桥接串行调度书架分页、目录和按需章节读取，设置超时、有限重试、请求间隔与缓存，避免循环刷新。
- 阅读时选书、翻段和跳章是 VS Code 内的正常交互；后台章节获取、必要分页、下一章准备及本地进度保存由系统完成。
- 浏览器关闭、插件重启及浏览器后台任务暂停后的恢复必须验证，不能要求用户反复手动启动或保持前台。
- 临时网络错误可有限重试；登录过期进入 NeedsLogin；访问验证进入 AccessBlocked，停止自动请求。日常操作中若必须反复人工处理非登录验证码，该路线不通过自动化验收，不以此降低需求。
- 未订阅章节返回明确的不可读状态，不购买、不自动订阅；账号网页自动订阅设置可能产生的副作用也必须核查。

实验伴随扩展放在 `labs/qidian/browser-companion/`，桥接程序放在 `labs/qidian/bridge/`；验证后再决定正式模块与安装打包方式。此前浏览器侧原型仅传递脱敏信号至自身存储；本轮新增的通信模块位于 src/infrastructure/local-bridge，配对扩展模板位于 browser-extension，模板随插件打包，不复用 labs 运行代码。辅助组件的一次性安装属于部署步骤，日常阅读不得依赖手动桥接或提取。

浏览器扩展官方文档确认内容脚本可以自动运行于匹配页面、读取 DOM 并向扩展传递信息，且可通过 Native Messaging 与本机程序通信。这证明候选机制存在，不证明起点会稳定允许整条链路。

### 自动化验收契约

1. 首次使用：系统打开官方登录页面；用户手动登录，系统自动检测有效会话，随后自动获取真实书架。
2. 日常使用：用户仅在 VS Code 选书或继续阅读；系统自动取目录、可读正文及下一章，自动保存本地进度，不要求操作浏览器。
3. 再次启动：系统自动启动所需组件并复用会话；有效会话不要求再次登录。
4. 登录过期：系统打开官方登录流程；登录成功后自动恢复原任务，不要求点击提取。
5. 风控、内容不可读、网络失败：返回明确状态；人工复制正文或手动翻网页不能算通过。
6. 上述流程是产品验收要求；第三方网站能否稳定满足，需要真实接入证据，目前不能承诺已实现或永久可用。
