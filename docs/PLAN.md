更新日期：2026-10-13（Asia/Shanghai）。此文件是唯一共享的方案与进度记录，随 Git 提交推送到 GitHub；本机私有实验数据不参与同步。

## 文档分工与开发入口

- `README.md` 仅介绍功能、运行要求、安装接入、使用命令和连接排查，不记录阶段结论、测试数量、实验经过或待办。
- `docs/PLAN.md` 统一记录设计决策、开发进度、验证证据、限制和后续工作；进入正式开发后继续遵守此分工。
- `AGENTS.md` 固化代码和文档边界，供后续开发遵循。

正式代码校验使用 `npm test` 和 `npm run test:extension`，构建使用 `npm run build`。交互验证入口 `npm run dev:live` 会打开隔离开发窗口，自动读取当前页书单、第一本书目录及第一章，再执行一次下一章；它属于开发验证流程，不作为常规阅读入口。

原型实验命令保留在 labs：`npm run check:labs`、`npm run probe:qidian`、`npm run login:qidian`、`npm run manual:qidian`、`npm run companion:qidian` 和 `npm run test:labs`。原型结果与正式本机服务分开，不作为正式功能的验收替代。

## 目标与当前结论

制作自用 VS Code 状态栏小说阅读器，首要书源是起点中文网，仅账号登录及重新登录允许手动操作；登录后自动读取个人书架、目录及账号有权阅读的章节，并保存本地阅读进度。先验证接入，再实现正式阅读体验。

当前结论：普通 Edge 配对伴随扩展与 VS Code 内置回环 HTTP 服务的接入路线已在本机验证。当前页 11 本书单、第一本书 225 章目录、第一章正文及切换第二章均经用户核对通过，正文评论计数已排除。已实现任务触发的专用 Edge 自动唤起、私有配对凭据刷新及旧工作进程一次性版本恢复；专用 Edge 完全退出并重启开发窗口后，自动复用登录取得书单、目录和前两章，无需手动重新加载。D01 窗口控制和 D02 自动隐藏读取已通过本机短时验收，用户确认连续读取到第四章并再次隐藏；长时间后台停留检查按用户要求取消。61 项正式单元/集成测试及真实 VS Code 宿主模拟任务测试通过。全量分页、真实解锁限制、登录失效后的任务恢复、跨重启阅读进度和正式状态栏阅读体验仍未验收，不能宣称完整起点接入已完成。

## 正式开发执行计划（2026-10-13 确定）

### 确定的运行行为

- 正常阅读：专用普通 Edge 窗口后台隐藏，书架、目录、正文和下一章均在 VS Code 操作。
- 登录或重新登录：显示专用浏览器供用户操作；确认登录有效后，自动恢复原任务并隐藏窗口。仅页面加载完成或弹窗消失不能认定登录成功。
- 访问受阻或读取失败：VS Code 提醒并停止本次任务，保留已成功读取的正文和阅读位置；不循环请求、不跳过失败章节、不自动购买或解锁。
- 需要排查：提供“显示辅助浏览器”和“隐藏辅助浏览器”命令。用户主动显示进入排查状态，自动任务不得立即再次隐藏；用户执行隐藏命令后恢复自动管理。

沿用已验证的普通 Edge、专用持久化配置和伴随扩展，不切换无头或远程调试运行方式。隐藏只控制窗口显示，浏览器进程与页面继续运行。仅管理能明确归属 IdlePage 专用配置的窗口，不影响用户日常 Edge。启动闪现、焦点变化和后台页面运行效果均需实机验收，当前不承诺全程零闪现。

### 执行顺序与验收

|---|---|---|

| D02 隐藏运行接入（短时验收完成） | 将窗口管理接入现有任务启动流程，正常任务后台加载页面，减少标签页激活、伴随页弹出和焦点切换；保持配对刷新与旧工作进程恢复 | 专用浏览器未运行时自动启动并隐藏，书单→目录→前两章通过；手动显示后第三章保持可见，手动隐藏后第四章仍隐藏，用户确认通过；按用户要求取消长时间停留检查，冷启动零闪现/焦点不作保证 |

| D04 正式书架与目录入口（用户验收通过） | 状态栏书本悬停菜单；原生书架/目录搜索列表；任意书籍与章节选择；全部刷新专用浏览器；诊断入口与日常流程分开 | 用户确认菜单及操作正常；任意目标选择、切换拒绝旧结果、原正文保留由测试覆盖；全量书架和分页继续暂缓 |
| D05 状态栏阅读体验 | 实现最初指定的底部状态栏正文展示、分段、前后翻段、下一章、快捷隐藏/恢复和必要设置；后台取章期间保留当前正文 | 在常用窗口宽度下可读；缩放或改变宽度后阅读位置稳定；快捷键不抢占常用编辑操作；不可获取时有明确提醒，原章仍可阅读 |
| D06 本地阅读进度 | 按书籍保存章节标识与正文字符位置，而非屏幕页码；在本机私有存储中恢复位置；重新启动后按需获取正文再定位 | VS Code 或浏览器重启后恢复同一本书和位置；改变显示宽度仍定位到对应文本；章节内容变化或失效时有可理解的回退；私有记录不进入 Git |
| D07 集成验收与交付 | 核验必要的回归测试、真实隐藏运行、登录恢复、失败保留、关闭恢复及配对更新；检查 VSIX 和辅助扩展发布边界，完善功能及接入说明 | 源码不依赖 labs；安装包不包含配对密钥、私有数据或实验产物；完成一次从安装到登录、选书、阅读、重启恢复的真实验收；README 只更新功能和使用说明，证据写在本文件 |

模块安排：窗口控制放在 `src/infrastructure/qidian/`，应用层复用并逐步整理 `BrowserSession` 的协调职责；阅读位置与章节状态放在 domain/application，正式展示与命令在 ui/extension。`tests/` 覆盖状态转换和错误恢复，真实网页与 Windows 隐藏运行单独记录人工/实机证据。避免只修改启动参数就宣称后台隐藏已经完成。

每阶段先实现可回退的最小范围，再完成与改动相关的自动校验和实机验收，记录结果并同步 Git。D01 和 D02 短时验收已完成，D03 已实现并通过当前有效会话下的实机恢复测试，真实失效登录保留待验；D04 书本悬停菜单与选书选章已通过用户验收；下一开发阶段为 D05 状态栏阅读体验。多服务窗口协调、全量分页、官方进度同步和购买功能不加入这一轮执行范围。

## 接入路线

### 首轮实验：Playwright 专用浏览器（暂受阻）

使用本机 Edge，独立浏览器配置，人工完成网站登录和验证码；工具仅观察当前页面 DOM，不自动点击、购买、破解验证或反复刷新。

自动化浏览器配置：`%LOCALAPPDATA%/IdlePage/qidian-probe/edge-profile`。

初轮 Playwright 默认参数带有 `--no-sandbox`，已改为 `chromiumSandbox: true` 并实测运行进程不包含该参数。但重新验证后仍触发验证，不能将其认定为唯一原因或已解决风控。单次诊断脚本会自动关闭浏览器，曾打断用户验证；常规 session 模式已保留窗口直至用户关闭。

### 优先后续路线：普通浏览器伴随扩展 + 自动任务桥接（待验证）

普通 Edge 对照配置：`%LOCALAPPDATA%/IdlePage/qidian-probe/manual-edge-profile`，不包含 Playwright 控制、不启用远程调试、不导出 Cookie。用户已反馈此配置能正常访问并登录。

2026-10-12 需求修订：登录之后不得依赖用户切换到浏览器、打开书架、翻页、打开章节、点击提取或复制 Cookie。手动提取桥接不满足要求，不再作为实现路线。

候选链路：VS Code 应用用例 → 本机任务桥接 → 普通浏览器伴随扩展 → 起点页面加载和内容脚本 → 结构化书架/目录/正文 → VS Code 状态栏。

候选分工：
- 普通浏览器保有账号会话，伴随扩展按任务自动加载官方书架或阅读页；登录时显示官方页面供用户操作。
- 内容脚本自动等待目标 DOM 就绪并提取结构化结果，不要求用户点击扩展按钮。
- 本轮采用 VS Code 扩展宿主内的回环 HTTP 服务验证任务往返；Native Messaging 保留为候选，浏览器启动恢复机制待验证。普通浏览器可登录不代表带伴随扩展自动加载页面也可用。
- 本机桥接串行调度书架分页、目录和按需章节读取，设置超时、有限重试、请求间隔与缓存，避免循环刷新。
- 阅读时选书、翻段和跳章是 VS Code 内的正常交互；后台章节获取、必要分页、下一章准备及本地进度保存由系统完成。
- 浏览器关闭、插件重启及浏览器后台任务暂停后的恢复必须验证，不能要求用户反复手动启动或保持前台。
- 临时网络错误可有限重试；登录过期进入 NeedsLogin；访问验证进入 AccessBlocked，停止自动请求。日常操作中若必须反复人工处理非登录验证码，该路线不通过自动化验收，不以此降低需求。
- 未订阅章节返回明确的不可读状态，不购买、不自动订阅；账号网页自动订阅设置可能产生的副作用也必须核查。

实验伴随扩展放在 `labs/qidian/browser-companion/`，桥接程序放在 `labs/qidian/bridge/`；验证后再决定正式模块与安装打包方式。此前浏览器侧原型仅传递脱敏信号至自身存储；本轮新增的通信模块位于 src/infrastructure/local-bridge，配对扩展模板位于 browser-extension，模板随插件打包，不复用 labs 运行代码。辅助组件的一次性安装属于部署步骤，日常阅读不得依赖手动桥接或提取。

浏览器扩展官方文档确认内容脚本可以自动运行于匹配页面、读取 DOM 并向扩展传递信息，且可通过 Native Messaging 与本机程序通信。这证明候选机制存在，不证明起点会稳定允许整条链路。

### 自动化验收契约

1. 首次使用：系统打开官方登录页面；用户手动登录，系统自动检测有效会话，随后自动获取真实书架。
2. 日常使用：用户仅在 VS Code 选书或继续阅读；系统自动取目录、可读正文及下一章，自动保存本地进度，不要求操作浏览器。
3. 再次启动：系统自动启动所需组件并复用会话；有效会话不要求再次登录。
4. 登录过期：系统打开官方登录流程；登录成功后自动恢复原任务，不要求点击提取。
5. 风控、内容不可读、网络失败：返回明确状态；人工复制正文或手动翻网页不能算通过。
6. 上述流程是产品验收要求；第三方网站能否稳定满足，需要真实接入证据，目前不能承诺已实现或永久可用。

### 官方合作接口

阅文提供合作方文学 API，需合作产品配置、appflag/appsecret 与 IP 白名单。个人账号书架及原有订阅权益是否可通过合作接口接入，未确认，因此不是当前自用实验的默认路线。
